# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This repo is the public API documentation site for **TTS OpenAI** (Text-to-Speech), served at docs.ttsopenai.com. It is a **Nuxt 3 + `@nuxt/content` v2** static docs site built on the `nuxt-ui-pro-template-docs` template (`@nuxt/ui-pro`). Nearly all "content" work is editing Markdown files, not Vue/TS code — the app shell (layouts, header, footer, search) is template boilerplate that rarely needs to change.

## Commands

Package manager is **pnpm** (`packageManager: pnpm@9.12.2`, `.npmrc` sets `shamefully-hoist=true`).

- `pnpm install` — install dependencies (runs `nuxt prepare` via `postinstall`)
- `pnpm dev` — start the dev server (hot reload for content and components)
- `pnpm build` — production build (SSR/Nitro output)
- `pnpm generate` — static site generation to `.output/public` / `dist` (this is what's used for deployment, see below)
- `pnpm preview` — preview a built app locally
- `pnpm lint` — ESLint over the whole repo (flat config in `eslint.config.mjs`, extends `.nuxt/eslint.config.mjs` generated by Nuxt)
- `pnpm typecheck` — `nuxt typecheck` (runs `vue-tsc`)

There is no test suite in this repo (no test runner/config present) — verification is `pnpm lint`, `pnpm typecheck`, and manually checking pages via `pnpm dev`.

## Architecture

### Content-driven routing (`@nuxt/content` v2)

- All documentation pages live under `content/` as Markdown files with YAML frontmatter (`title`, `description`, and optional `navigation: false`).
- Directory/file names are prefixed with numbers (`1.getting-started/`, `2.resources/1.tts-text.md`, ...) to control sidebar/nav ordering. Each content directory has a `_dir.yml` that sets the section's display `title` in the nav.
- `content/index.yml` drives the landing page (`app/pages/index.vue`) — hero copy, code sample, and feature grid are all data, not markup.
- A single catch-all page, `app/pages/[...slug].vue`, renders every content page: it queries the current route via `queryContent()`, renders the body with `<ContentRenderer>`, builds the "surround" (prev/next) links, and the right-hand table of contents. To add a new doc page, add a Markdown file under `content/` — no route/page code is needed.
- `server/api/search.json.get.ts` exposes all markdown content (excluding pages with `navigation: false`) for the client-side search (`UContentSearch`), wired up in `app/app.vue`.

### Markdown conventions used in `content/`

- Every page starts with frontmatter: `title` + `description` (used for page header, SEO, and OG image via `defineOgImageComponent('Docs')`).
- API endpoints are documented with a `::code-group` block containing parallel `bash`/`py`/`ts` examples (curl, Python `requests`, TS `axios`), followed by an "Example Response" JSON block.
- Request/response fields are documented as inline code with a styled type annotation, e.g.:
  `` `field_name` [string]{style="color: rgb(var(--color-gray-400) / var(--tw-text-opacity, 1)); font-weight: 300;"} ``
  followed by a one-line description. Follow this exact pattern for new field docs rather than using tables.
- Callouts use the `::callout` component (optionally with `icon`, `target`, `to` in the YAML-ish block) for tips/notes.
- `UButton`/`UIcon` are the only components registered as globals for use directly inside `.md` files (see the `components:extend` hook in `nuxt.config.ts`); other components must stay in `.vue` files.

### App shell

- `app/app.vue` — root: header, footer, loading indicator, lazy-loaded content search, and provides `navigation` (from `fetchContentNavigation()`) to descendants.
- `app/layouts/docs.vue` — two/three-column docs layout (left nav tree from `navigation`, page content, right ToC).
- `app/components/AppHeader.vue` / `AppFooter.vue` — header/footer, configured mostly through `app/app.config.ts` (logo, nav links, social links, footer credits/ToC bottom links).
- `app/app.config.ts` is the place to change site-wide chrome: header links, footer links, `toc.bottom.edit` (GitHub "edit this page" base URL), primary color (`green`), etc. Prefer editing this over hardcoding values in components.
- Custom brand color `green` and font (`DM Sans`) are defined in `tailwind.config.ts`.

### Deployment

- `Dockerfile` builds the static site (`pnpm run generate`) in a `build` stage; the final stage only contains `.output`. Deploys go to **Cloudflare Pages** via `wrangler pages deploy` using `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`.
- `Jenkinsfile` is the CI/CD pipeline: `develop` branch deploys to the `dev` Cloudflare Pages project, `main` deploys to `prod` (see `getEnvCode`). It builds the Docker image, runs `wrangler pages deploy` inside it, then removes the local image, with Slack notifications to `tts-cicd-notify` on start/success/failure.
- `deployment/` (Ansible playbook + roles) is an alternate/legacy deployment path (`frontend_deployment` role: install deps → `pnpm run generate` → build Docker image → deploy) — check `deployment/group_vars/{dev,prod}.yml` and `deployment/inventories/` before assuming it's what's actively used; the Jenkinsfile is the primary pipeline.

## Editing guidelines specific to this repo

- New API documentation should go under `content/2.resources/` (one file per endpoint/resource) or `content/1.getting-started/` for onboarding/auth/webhook-style guides; update the corresponding `_dir.yml` only if adding a new top-level section.
- Keep numeric filename prefixes consistent with sibling files so sidebar ordering stays correct when inserting a new page.
- Real API base URL referenced throughout docs is `https://api.ttsopenai.com/uapi/v1/...`; the marketing/app site is `https://ttsopenai.com`. Don't mix these up when adding links.
- ESLint stylistic rules (`eslint.config.mjs` via `nuxt.config.ts`): no trailing comma (`commaDangle: 'never'`), 1tbs brace style.
